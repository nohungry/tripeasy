# P4 交易 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

> 狀態：**草稿**（2026-11-24，待使用者審閱後才開工）

**Goal:** 交易流程（購物車 → 結帳 → 優惠券／點數 → 藍新付款 → 結果）從前端能完整操作；付款成功的結算正確、冪等、可在 DB 驗證；藍新以本機 `mock-newebpay` 模擬；管理員退款 API；主線有 E2E；最後寫 P4 報告、合併、打 tag。

**Architecture:** DB 用 versioned migration `V5` 給 `payment` 加 `merchant_order_no` 與「一張訂單最多一筆成功付款」的部分唯一索引。後端新增兩個工具模組：`src/utils/trade.js`（訂單狀態常數、**唯一的應付金額函式**、折扣評估、保留與釋放、逾時判斷、結算）與 `src/utils/newebpay.js`（AES／SHA 與 HTML 跳脫），購物車、結帳、折扣、藍新、退款的 controller 都呼叫它們。`mock-newebpay` 是總覽 repo 內的 Node 內建 `http`＋`crypto` 小服務，扮演藍新：驗簽、顯示付款頁、伺服器端簽 notify、瀏覽器導回 ReturnURL。測試端用 Python 簽章工具 `tests/newebpay.py` 直接自簽 notify 做竄改、重送案例；E2E 走 mock 的真實頁面。

**Tech Stack:** Express 4.21 + raw `pg` + Joi 17、PostgreSQL 15、Flyway 10.20.1、Node 22 內建 `crypto`／`http`、Vue 3 + vue-router（hash）+ axios + sweetalert2、Python 3.13 / uv / pytest 8.3.3 / requests / psycopg 3.2.3 / pytest-playwright 0.5.2，測試端新增 `cryptography`。

**Spec:** `docs/superpowers/specs/2026-11-24-p4-trade-design.md`（以下稱「P4 spec」）；上位 `docs/superpowers/specs/2026-10-15-tripeasy-rebuild-design.md`（「總 spec」）。契約：`docs/db-contract.md`。前一階段：`docs/reports/phase-3.md`（「P3 報告」）與 P3 ledger `.superpowers/sdd/2026-11-19-p3-product/progress.md:177,181`。

## Review Focus

1. **同一 notify 併發送兩次**（不只是先後重送）：兩個請求同時到，只能結算一次、不得 500。→ Task 8 `test_notify_concurrent_duplicates_settle_once`。

5. **付款頁停留到交易時限之後才按付款成功**：mock 顯示 `交易逾時`、不送成功 notify，訂單維持 0 且之後可被判逾時。→ Task 7 `test_mock_refuses_after_trade_limit`；Task 8 `test_order_expires_after_attempt_deadline`。
